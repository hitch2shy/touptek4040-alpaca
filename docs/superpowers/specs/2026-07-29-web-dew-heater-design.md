# Web 防雾加热控制设计

## 目标

为 ToupTek `sMAX16AM-U3-CL-GPS` 增加官方 SDK 支持的防雾加热控制，使主控软件通过 Alpaca 连接相机时，操作者仍可在 Web GUI 中独立查看、开启、关闭和调节加热档位。

本功能不得改变或扩展 ASCOM Alpaca Camera V4 的标准接口。

## 官方 SDK 对齐

设备只读枚举已确认 `TOUPCAM_FLAG_HEAT` 为真。

功能严格使用以下 SDK 定义：

- `TOUPCAM_FLAG_HEAT`：设备支持防雾加热。
- `TOUPCAM_OPTION_HEAT_MAX`：只读最大档位。
- `TOUPCAM_OPTION_HEAT`：读写当前档位。
- 档位 `0` 表示关闭，`1` 至设备报告的最大档位表示开启。

不得假设固定最大档位。每次连接都从设备读取并验证最大档位。

## 接口范围

### 保持不变

- ASCOM Alpaca Camera V4 路由清单。
- `SupportedActions` 的现有行为。
- Alpaca `Action` 的现有行为。
- N.I.N.A. 等主控软件看到的 Camera V4 属性和方法。

### 新增内部能力

内部相机契约增加：

- 是否支持防雾加热。
- 防雾加热最大档位。
- 当前防雾加热档位。
- 设置防雾加热档位。

这些能力只供 owner、协调器、Web API、Web GUI、测试和诊断使用，不注册为 Alpaca Camera 端点。

## 运行架构

真实相机运行时，只有 owner 子进程可以导入 ToupTek SDK wrapper、加载 `toupcam.dll`、持有相机句柄或调用加热选项。

数据流为：

```text
Web GUI
  -> Web API
  -> CameraCoordinator
  -> CameraOwnerProxy
  -> owner IPC
  -> ToupTekCamera
  -> TOUPCAM_OPTION_HEAT / HEAT_MAX
```

Web 层不得直接导入 SDK，也不得绕过 owner 访问相机。

模拟器在主进程内实现相同内部契约，不启动 owner 进程。

## 状态与控制规则

### 连接状态

- 未连接时，Web 显示加热不可用。
- 连接后，读取设备支持标志、最大档位和当前档位。
- 不支持 `TOUPCAM_FLAG_HEAT` 时，显示“不支持防雾加热”，不执行任何加热写入。

### 档位

- Web 提供“关闭”和 `1..最大档位`。
- 发送值必须是精确整数；拒绝布尔值、小数、字符串数值、负数和超过最大档位的数值。
- 设置成功后重新读取当前档位，并以设备返回值更新界面。
- 不提供百分比换算，避免隐藏真实硬件档位。

### 与主控连接的关系

- Alpaca 主控保持连接时，Web 可以独立读取和调整加热。
- 加热调整不改变 Alpaca `Connected` 状态。
- 加热调整不自动改变 TEC 制冷开关、目标温度或风扇。

### 与曝光的互斥

- 加热器可以在曝光期间继续以当前档位工作。
- 曝光正在进行时，Web 仍显示最后确认的档位，但调整控件禁用。
- 服务端同时执行强制检查；即使绕过界面直接提交请求，也拒绝在曝光期间改变档位。
- 曝光结束或终止后，Web 恢复调整能力。

### 断开与退出

- 每次成功连接时记录连接前的原始加热档位。
- 主控断开、GUI 退出、服务停止或 owner 正常清理时，在关闭句柄前恢复该原始档位。
- 恢复动作必须位于清理 `finally` 路径中。
- 恢复失败必须记录真实错误；不得报告恢复成功。
- owner 超时或被强制终止时无法保证执行设备写入。替换 owner 保持断开，必须由客户端显式重新连接；重新连接后重新读取设备真实档位，不沿用缓存猜测。

## Web GUI

相机设置区增加“防雾加热”控件：

- 状态文本：未连接、不支持、关闭、档位 N、读取失败。
- 档位选择：关闭、1 至设备最大档位。
- 忙碌提示：曝光期间显示“拍摄中，暂不可调整”。
- 设置失败后恢复到最后一次设备确认的档位，并显示错误。

Web 状态响应新增内部字段：

- `heaterSupported: bool`
- `heaterLevel: int | null`
- `heaterMaxLevel: int | null`
- `heaterWritable: bool`

Web 写入请求只接受：

```json
{
  "heaterLevel": 0
}
```

不增加公开 Alpaca Camera 路由。

## 错误处理

- 未连接：返回稳定的未连接错误。
- 不支持加热：返回稳定的不支持错误。
- 非整数或越界：返回输入错误，不调用 SDK。
- 正在曝光：返回相机忙错误，不调用 SDK。
- SDK 读取或写入失败：传播为稳定的相机错误，记录 owner 诊断。
- IPC 超时或损坏：按 owner 隔离规则终止准确的 owner 进程，不自动重试写入，替换 owner 保持断开。
- 写入响应丢失时不得自动重发，以免重复执行未知状态的硬件操作。

## 测试与证据

### 单元测试

- 支持标志、最大档位和当前档位读取。
- `0` 关闭及 `1..最大档位` 写入。
- 非法类型、负数和越界值不调用 SDK。
- 不支持加热的相机不调用 SDK。
- 加热操作不改变 TEC、目标温度或风扇。
- 模拟器实现内部契约但不启动 owner。

### owner 与协调器测试

- 加热 SDK 调用只发生在 spawned owner PID。
- 主控连接期间 Web 加热请求可用。
- 曝光期间读取可用、写入被拒绝且 SDK 调用次数为零。
- 并发写入经协调器和 owner 顺序执行。
- 加热 IPC 超时不重试，替换 owner 保持断开。
- 正常断开和退出恢复原始档位。

### Web 测试

- 状态字段和控件状态正确。
- 档位选择按设备最大值生成。
- 曝光期间控件禁用，服务端同时拒绝写入。
- 不支持、失败、断线和重新连接状态正确显示。

### 真机测试

- 确认型号和序列号后才允许写入。
- 快照加入 `heat` 和 `heat_max`。
- 读取设备最大档位。
- 在安全受控步骤中切换一个有效档位，再恢复原始档位。
- 每个测试都在 `finally` 中恢复，并重新读取确认。
- 最终证据必须报告恢复是否成功、是否关闭句柄以及是否存在 owner 遗留。
